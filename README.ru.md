## Зачем

Интерфейсы всё чаще пишут кодинг-агенты. Работают они быстро, а их страницы легко узнать: градиент в шапке,
одна и та же палитра без объяснения выбора, стеклянные панели, эмодзи вместо иконок, три карточки в ряд, длинное тире в каждом предложении, «это не X, это Y». <!-- design-tells: ignore --> По отдельности всё это нормально. Вместе получается
«здесь никто ничего не решал», и странице доверяют меньше.

Обратная проблема тише. Агенты пропускают простые вещи: настоящие скриншоты, состояния загрузки и пустого списка,
ошибки, с которыми можно что-то сделать, фокус с клавиатуры. А в отчётах пишут длинные сводки, где результат спрятан
где-то в середине.

telltale я теперь даю каждому агенту, прежде чем он возьмётся за интерфейс. Это короткий процесс, список признаков с
заменами, базовые вещи, о которых забывают, и правила письма для текстов интерфейса и для отчётов самого агента.

## Что делает агент

| Шаг | Что происходит |
| --- | --- |
| **Решить** | Называет тему, аудиторию и где страницей пользуются. Выбирает режим: «убедить» (лендинг), «работать» (админка, дашборд), «читать» (документация) или «впечатлить» (игры). Сначала читает дизайн-систему проекта и отмечает достоинства, которые нужно сохранить. Пишет план из пяти строк и проверяет привычные решения по брифу. |
| **Выбрать цвета** | Учитывает существующую палитру и предпочтения. Если направление открыто, показывает 2–3 палитры на одном интерфейсе, уточняет выбор вместе с вами и сохраняет его. Проверяет контраст отдельно от вкуса. |
| **Собрать систему** | Токены по ролям (`--bg`, `--surface`, `--accent`, статусы), тёмная тема как второй набор токенов, маленькая шкала шрифтов, отступы с шагом 4 px. |
| **Собрать интерфейс** | Иерархия через вес, цвет и отступы. Карточки только там, где они нужны. Все состояния у каждого компонента. Честные данные: единицы, выровненные цифры, статус не только цветом. Движение только как смена состояния. |
| **Писать для человека** | Принципы ASD-STE100: одно слово на одно значение, короткие предложения, одно действие в предложении, условие до действия, предупреждение до шага. Отчёт начинается с результата и того, что нужно сделать вам. |
| **Проверить** | Скриншоты на 390, 768 и 1440 px в поддерживаемых темах; до/после при одинаковых размерах окна и теме. Отдельная оценка впечатления и выполнения задачи. До трёх раундов исправлений, проход с клавиатуры, сканер. Агент сообщает только выполненные проверки. |

**Ваш бриф главнее.** Явная просьба или существующая дизайн-система проекта сильнее стилевых рекомендаций. Осознанное
решение остаётся, с одной строкой о причине. Требования к контрасту, рекомендации по сочетаниям и личные предпочтения
рассматриваются отдельно. Сочетания цветов, чистый белый и чёрный допустимы сами по себе.

**Палитры сравниваются на настоящем экране.** Шрифты, текст, изображения, состояние, размер окна и тема остаются
одинаковыми. Вы можете выбрать вариант, совместить элементы или описать изменение обычными словами. Агент уточняет
выбранное направление и проверяет новое сочетание. При уже заданной палитре или поручении выбрать самому этот раунд
не обязателен.

Начать можно с фирменного цвета, изображения-референса или цветового сочетания. Выбранные значения закрепляются,
остальные уточняются по просьбам «теплее» или «менее насыщенно». Агент разворачивает палитру в роли и состояния интерфейса,
проверяет закреплённые значения и сохраняет предыдущие варианты. Расчёты и превью выполняются локально.
Adobe Color, Coolors и Colormind служат примерами подходов к выбору; подключать их API не требуется.

**Типографика проверяется в отрисованном интерфейсе.** Агент читает реальные слова в рабочем размере и в уменьшенном
превью, которое передаёт пользователю. Плотный интервал не должен сливать буквы, например `rn` в `m`. После изменения
шрифта или интервала агент также проверяет переносы рядом с границами адаптивных режимов.

<details>
<summary><strong>Про ASD-STE100</strong></summary>

ASD-STE100 Simplified Technical English (упрощённый технический английский) это авиационный стандарт для документации по
техобслуживанию. Механики читают такие тексты в спешке, часто на неродном языке, и неверно понятый шаг стоит дорого. В
стандарте есть контролируемый словарь и около шестидесяти правил письма.

Словарь и точный текст правил английские и принадлежат ASD (выдаются бесплатно по запросу). telltale не копирует ни то,
ни другое. Он берёт принципы, которые работают на любом языке и заодно делают агента понятнее для человека:

- один термин для одной вещи, термины записаны в глоссарий проекта;
- шаги не длиннее 20 слов, описания не длиннее 25;
- одно действие в предложении, в повелительном наклонении;
- действительный залог, названо, кто действует;
- условие до действия, предупреждение до шага.

Для отчётов скилл добавляет постоянный порядок: результат и что нужно сделать вам, потом изменения, потом что проверено
и что нет.

</details>

<details>
<summary><strong>Юридические страницы: когда нужны</strong></summary>

Публичному продукту и любой форме, где собирают персональные данные, нужны условия использования и политика
конфиденциальности. Внутреннему инструменту за входом для сотрудников обычно нет. Если аудитория неясна, агент спросит
вас. По умолчанию он не добавляет юридические страницы и не отмечает их отсутствие как ошибку.

</details>

## Установка

**Claude Code.** Скопируйте папку скилла:

```bash
# для всех проектов
cp -r skills/telltale ~/.claude/skills/
# или для одного проекта
cp -r skills/telltale <проект>/.claude/skills/
```

Claude подхватит скилл, когда задача про интерфейс. Можно вызвать и явно: `/telltale`.

**Codex и другие агенты, которые читают `AGENTS.md`.** Скопируйте `skills/telltale` в проект и добавьте пункты из
[`AGENTS.md`](AGENTS.md) в `AGENTS.md` проекта (или в `~/.codex/AGENTS.md`, чтобы работало везде).

## Сканер

```bash
python skills/telltale/scripts/check_design_tells.py путь/к/проекту
python skills/telltale/scripts/check_design_tells.py page.html --strict   # код возврата 1, если что-то нашлось
python skills/telltale/scripts/check_design_tells.py src --json           # для CI и агентов
```

Он читает HTML, CSS, JS, TS, JSX, TSX, Vue, Svelte и Markdown и выводит кандидатов с файлом и строкой. Сам ничего не
правит. Кандидат означает «посмотри сюда», а решение за вами: ряд плиток с цифрами уместен в операционном дашборде и
может быть неуместен на лендинге. Значения цветов сами по себе не считаются находками. Этот сканер исходников
не измеряет контраст отрисованного интерфейса или его привлекательность.

Осознанное место помечается на его строке комментарием `design-tells: ignore`, целый файл (например, гайд по стилю)
пометкой `design-tells: ignore-file`. Нужен Python 3.8 или новее, зависимостей нет.

```text
"Not X, but Y" construction [not-x-but-y]: 1  ->  Say what it is, directly
  landing.html:1  <h1>It's not a tool, it's a revolution ...

Basics not found (check whether they apply):
  - Empty state [empty-state]
  - Error state [error-state]

23 candidate(s), 6 basic(s) not found.
```

## Реальный прогон

Первой целью была внутренняя админка: 2155 строк HTML, CSS и JS, которые агенты писали несколько недель.

| | До | После |
| --- | --- | --- |
| Кандидаты | 127 | 17, все оставлены осознанно |
| Длинные тире в текстах | 41 | 0 |
| Цветные полоски слева | 7 | 0, теперь полные рамки |
| Подписи заглавными с разрядкой | 4 правила | 0, обычный регистр |
| Градиенты, стекло, фиолетовый, эмодзи | не было | нет |

Оставшиеся 17 оставлены специально: скругления у меток и индикаторов, пульсирующая точка «онлайн» с учётом reduced
motion и тире как «нет значения» в ячейках таблиц. Юридических страниц нет: это внутренний инструмент.
Исторические числа получены прежним набором правил; текущий сканер не отмечает цвет сам по себе. Количество кандидатов не измеряет визуальное качество.

## Источники

Все идеи пересказаны своими словами, тексты не копировались. Скиллы Anthropic `frontend-design` и `canvas-design`
(Apache-2.0), Impeccable Пола Бакауса (Apache-2.0), taste-skill (MIT), Vercel Web Interface Guidelines (MIT), заметка
OpenAI о фронтенде с GPT-5.4, книга Refactoring UI, Laws of UX, WCAG 2.2 (критерии по номерам), Apple HIG, Material
Design и ASD-STE100 (только принципы). Первый список признаков взят из публикации в сообществе.
